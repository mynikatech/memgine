# Counter order lifecycle validation

All cases are **NOT EXECUTED**. The immediate checkout, advance terminal, and final Support resolution rows describe acceptance targets for capabilities that remain open. Use a disposable LOCAL database with synthetic membership, Store and checkout records. Keep live providers disconnected. Use repository-approved capture fixtures when available.

For the order actions below, use `POST /api/v1/organizations/{org}/counter/orders/{id}/actions/{action}?storeId={store}&staffId={staff}`. Use the version from the scoped order detail response. A response code in the table is the API result or conflict code.

## LOCAL preview and application gate

Run the following read-only query in the configured LOCAL and DEV Liquibase changelog schemas before preview or application. Compare the existing collection and lifecycle file checksums with the records. File presence and Git status cannot establish application status.

```sql
SELECT id, author, filename, dateexecuted, md5sum
FROM databasechangelog
WHERE id IN (
  '309c-counter-order-collection',
  '309c-counter-order-lifecycle'
)
ORDER BY orderexecuted;
```

After baseline confirmation and with approved LOCAL credentials in the repository's LOCAL Liquibase properties, generate the preview from the repository root.

```powershell
.\DB\scripts\liquibase-update-sql.ps1 -Environment local
```

The opt-in concurrency test expects a **pre-migrated disposable** database named `memgine_309c_test` on loopback, two authorized staff members at the same Store, and a fresh, free, READY fixture. Its environment prefix is `MEMGINE_309C_TEST_` with suffixes `JDBC_URL`, `SCHEMA`, `USER`, `PASSWORD`, `ORG`, `STORE`, `STAFF`, `ACTOR`, `SECOND_STAFF`, `SECOND_ACTOR`, `ORDER` and `QR`. It commits one collection only when `MEMGINE_309C_POSTGRES_TEST=1`. Run only under separate test authorization.
